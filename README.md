# 救救我的通知！

> Oh My Notification! 把被误划掉的 Android 通知捞回来。

“救救我的通知！”是一个本地优先的通知历史工具。它会保存系统交付给它的通知，按应用和时间整理，并在原通知动作仍然有效时尝试带你回到原内容。

不做账号，不做云同步，不上传通知，也不把通知改造成另一套待办清单。

## 为什么做

起因很朴素：我老是手滑划掉 B 站推送，等反应过来，通知已经没了；偏偏手机自己的通知历史又只肯留下最近几条。

试过的现成工具要么漏记、重复和排序混乱，要么只能保存文字、不能回到原内容。既然真正想救的是“那条还能点开的通知”，就干脆自己做一个。

## 能做什么

- 把通知保存在本机，系统通知被划掉后仍可回来查看。
- 合并同一条通知的后续更新，减少重复记录。
- 按稳定时间线排列通知；连续出现的同一应用会收进一个默认展开的小抽屉。
- 按一个或多个应用筛选记录，也可以停止记录指定应用。
- 分别控制媒体、消息与通话、提醒与导航、持续运行与进度等通知类型；媒体通知默认关闭。
- 在通知栏常驻一张低打扰状态卡，显示监听是否正常和最近记录摘要。
- 单条或批量归档通知，归档后可撤销；在已归档通知中恢复或确认后永久删除。
- 批量仅查看、隐藏或调整所选来源的监控；全选包括当前筛选下尚未载入的记录。
- 首次进入时提供可跳过的权限与后台运行引导，设置页可重新查看。
- 在设置页手动检查 GitHub 正式版本，下载并验证后交给系统安装器。
- 在设置页“故障排查”中手动导出近期运行日志，遇到问题时可附上日志到 GitHub 提交 Issue。

## 安装后怎么用

1. 安装并打开应用。
2. 按首次引导开启“通知使用权”。这是记录通知所必需的系统权限；引导可以跳过，跳过授权后无法记录。
3. 允许应用发送通知。这个权限只用于显示 OMN 自己的常驻状态卡。
4. 确认首页显示“正在记录通知”后即可离开应用。常驻状态卡也会显示异常，请留意其中的状态，不要只看它是否存在。

应用抽屉标题右侧的菜单用于管理整个来源：

- **不要再记录此 App**：以后不再保存该应用的新通知，已有历史保留。
- **仅查看此 App**：暂时只看这个应用，不改变后台监控范围。
- **不查看此 App**：从当前列表隐藏这个应用，不停止记录。

更多通知类型、抽屉时间间隔、来源排除和“已归档通知”都在设置页中。标题右侧菜单中的“批量操作”或长按通知可进入多选。

## 关于“打开原内容”

OMN 保存的是来源应用放进通知里的 Android 动作，而不是自己猜一个链接。因此，通知被划掉后仍然可能成功回到对应视频、动态或消息；但这个能力不能保证永久有效。

以下情况可能导致跳转失效：

- 来源应用主动取消了动作；
- OMN 或来源应用的进程重建后，系统没有重新提供该动作；
- 手机重启或覆盖升级后，原通知动作无法恢复，尤其是已经从系统通知栏划除的通知；
- 原内容已经删除、失效或需要重新登录；
- 来源应用本身只提供了打开首页的通知动作。

当前没有可用动作的记录和手动归档的记录统一进入“已归档通知”。你可以在那里要求 OMN 重扫一次系统当前仍活动的通知；找不到同一条通知时，OMN 不会假装成功，也不会擅自打开应用首页。取消手动归档后，如果仍没有动作，记录会继续留在归档页。

## 数据与隐私

- 没有遥测、广告或远程账号。网络权限仅用于用户主动检查、下载 GitHub 更新，不在启动或后台自动检查。
- 更新安装前核对 SHA-256、包名、递增版本号和当前签名证书，仅在安装时请求允许安装未知应用。
- 通知内容、设置和运行时动作只保存在设备本地。
- 不读取联系人、账号或其他应用的私有数据。
- 基础日志只滚动保留最近 256 条关键状态事件，不含通知正文、跳转链接或凭证，不自动上传；细粒度诊断默认关闭。
- 卸载应用会删除本地通知历史；v1 暂无通知历史的导出和恢复功能，诊断日志不能用来恢复通知。

## 已知边界

- 目前只支持 Android 16 及以上。
- Android 厂商的后台管理仍可能中断通知监听；OMN 无法为自己保活，请手动设置电池优化项或后台锁定等保活操作。
- 跳转依赖来源通知提供的动作，OMN 无法为没有精确目标的通知制造可靠链接。
- 1.1.0 尚未解决所有通知跨重启或覆盖升级后的跳转保留问题；失去动作的记录仍保留文字，可在“已归档通知”中查看，但不能保证重新打开原内容。
